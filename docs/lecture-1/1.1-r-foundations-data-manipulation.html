1.1 R Foundations and Data Manipulation

Author

Hua Gong

1 Learning objectives

After completing this tutorial, you should be able to:

  1. use R for arithmetic and vectorized calculations;
  2. distinguish vectors, factors, lists, matrices, arrays, data frames, and tibbles;
  3. extract values with [, [[, and $;
  4. calculate a transpose, determinant, inverse, and matrix product;
  5. solve a system of linear equations and connect matrix algebra to regression;
  6. manipulate a sports data frame with core dplyr verbs; and
  7. write a readable pipeline with %>% and handle missing values explicitly.

2 R as a calculator

R follows the usual order of operations. Parentheses make the intended calculation clear.

2 + 3 * 4
[1] 14
(2 + 3) * 4
[1] 20
sqrt(81)
[1] 9
log(exp(2))
[1] 2
choose(10, 2)
[1] 45

Common arithmetic operators are +, -, *, /, ^, and %% for the remainder. Use <- to assign a result to an object.

field_goals <- 4
extra_points <- 2
team_points <- 3 * field_goals + extra_points
team_points
[1] 14

Most R functions are vectorized: one operation is applied to every element of a vector.

yards <- c(4, -2, 12, 7, 0)

yards + 1
[1]  5 -1 13  8  1
yards > 5
[1] FALSE FALSE  TRUE  TRUE FALSE
sum(yards)
[1] 21
mean(yards)
[1] 4.2

Computers store most decimal values approximately. Use all.equal() rather than exact equality for a numerical comparison that may contain floating-point rounding.

0.1 + 0.2 == 0.3
[1] FALSE
all.equal(0.1 + 0.2, 0.3)
[1] TRUE

3 Core data structures

The data structure determines how values are stored and how they can be indexed.

Structure Dimensions Can mix types? Typical use
Atomic vector One No One measured variable
Factor One Categories with defined levels Positions, teams, or game states
List One Yes Nested or irregular objects
Matrix Two No Linear algebra and model design matrices
Array Two or more No Repeated measurements over several dimensions
Data frame or tibble Two Yes across columns Rectangular analysis data

3.1 Atomic vectors

An atomic vector contains values of one basic type. Important types include logical, integer, double, character, and date-time values.

completed_passes <- c(18L, 22L, 15L)
completion_rates <- c(0.64, 0.71, 0.58)
teams <- c("BUF", "KC", "PHI")
made_playoffs <- c(TRUE, TRUE, TRUE)

typeof(completed_passes)
[1] "integer"
length(teams)
[1] 3

When incompatible types are combined, R converts them to a common type. This behavior is called coercion.

c(1, TRUE, "BUF")
[1] "1"    "TRUE" "BUF"

Missing values are represented by NA. Many summary functions require an explicit decision about whether to remove them.

snap_counts <- c(62, 58, NA, 71)

mean(snap_counts)
[1] NA
mean(snap_counts, na.rm = TRUE)
[1] 63.66667
is.na(snap_counts)
[1] FALSE FALSE  TRUE FALSE

3.2 Factors

A factor stores categorical values and their allowed levels. Set the level order deliberately when it carries meaning.

game_phase <- factor(
  c("regular season", "postseason", "regular season"),
  levels = c("preseason", "regular season", "postseason")
)

game_phase
[1] regular season postseason     regular season
Levels: preseason regular season postseason
levels(game_phase)
[1] "preseason"      "regular season" "postseason"

3.3 Lists

A list can contain objects of different types and sizes. Lists are common in JSON responses and model output.

player <- list(
  name = "Example Quarterback",
  position = "QB",
  weekly_yards = c(245, 310, 278),
  active = TRUE
)

player$position
[1] "QB"
player[["weekly_yards"]]
[1] 245 310 278
player["weekly_yards"]
$weekly_yards
[1] 245 310 278

[[ extracts the object stored in one list element. [ returns a smaller list. $ extracts a named element and is convenient for interactive work.

3.4 Matrices and arrays

A matrix is a two-dimensional atomic vector. Every cell therefore has the same type.

  dimnames = list(

3.5 Data frames and tibbles

A data frame is rectangular: each row is an observation and each column is a variable. Columns may have different types, but every column must have the same number of rows. A tibble is a modern data frame with more readable printing and stricter behavior.

games <- tibble(

  home_team = c("BUF", "KC", "PHI", "SF", "BUF", "KC", "PHI", "SF"),

4 Matrix calculations

Matrix algebra is the language behind linear regression, principal components, optimization, and many machine-learning algorithms.

Let

A=[2113],b=[57]. A= \begin{bmatrix} 2 & 1\\ 1 & 3 \end{bmatrix}, \qquad b= \begin{bmatrix} 5\\ 7 \end{bmatrix}. 

A <- matrix(c(2, 1, 1, 3), nrow = 2, byrow = TRUE)
b <- c(5, 7)

A
     [,1] [,2]
[1,]    2    1
[2,]    1    3
b
[1] 5 7

4.1 Transpose, identity, and determinant

The transpose A𝖳A^\mathsf{T} exchanges rows and columns. An identity matrix has ones on its diagonal and behaves like the number 1 in matrix multiplication.

t(A)
     [,1] [,2]
[1,]    2    1
[2,]    1    3
diag(2)
     [,1] [,2]
[1,]    1    0
[2,]    0    1
det(A)
[1] 5

For this matrix,

det⁡(A)=(2)(3)−(1)(1)=5. \det(A)=(2)(3)-(1)(1)=5.

Because the determinant is not zero, AA is invertible.

4.2 Element-wise and matrix multiplication

A * A multiplies corresponding cells. A %*% A performs matrix multiplication.

A * A
     [,1] [,2]
[1,]    4    1
[2,]    1    9
A %*% A
     [,1] [,2]
[1,]    5    5
[2,]    5   10

For matrices Am×nA_{m\times n} and Bn×pB_{n\times p}, the product ABAB has dimension m×pm\times p, and

(AB)ij=∑k=1naikbkj. (AB)_{ij}=\sum_{k=1}^{n}a_{ik}b_{kj}.

4.3 Inverse and a linear system

The inverse A−1A^{-1} satisfies AA−1=IAA^{-1}=I.

A_inverse <- solve(A)
A_inverse
     [,1] [,2]
[1,]  0.6 -0.2
[2,] -0.2  0.4
round(A %*% A_inverse, digits = 10)
     [,1] [,2]
[1,]    1    0
[2,]    0    1

For a 2×22\times2 matrix,

[abcd]−1=1ad−bc[d−b−ca]. \begin{bmatrix}a&b\\c&d\end{bmatrix}^{-1} =\frac{1}{ad-bc} \begin{bmatrix}d&-b\\-c&a\end{bmatrix}.

Therefore,

A−1=15[3−1−12]. A^{-1}=\frac{1}{5} \begin{bmatrix}3&-1\\-1&2\end{bmatrix}.

Solving Ax=bAx=b gives x=A−1bx=A^{-1}b.

x <- solve(A, b)
x
[1] 1.6 1.8
A %*% x
     [,1]
[1,]    5
[2,]    7

In numerical work, prefer solve(A, b) to calculating solve(A) %*% b. It is usually faster and more stable. An inverse does not exist for a singular matrix, and a nearly singular matrix can produce unstable results.

4.4 Connection to linear regression

For the linear model

y=Xβ+ε, y=X\beta+\varepsilon,

the ordinary least-squares estimate is

β̂=(X𝖳X)−1X𝖳y. \widehat{\beta}=(X^\mathsf{T}X)^{-1}X^\mathsf{T}y.

The first column of XX contains ones for the intercept. The second contains an illustrative turnover margin.

turnover_margin <- c(-2, -1, 0, 1, 2)
points_scored <- c(17, 20, 24, 27, 31)

X <- cbind(intercept = 1, turnover_margin = turnover_margin)
y <- points_scored

beta_hat <- solve(t(X) %*% X, t(X) %*% y)
beta_hat
                [,1]
intercept       23.8
turnover_margin  3.5
coef(lm(points_scored ~ turnover_margin))
    (Intercept) turnover_margin 
           23.8             3.5

The two calculations agree. In practice, lm() uses a numerically safer matrix decomposition rather than forming the inverse directly.

5 Data manipulation with dplyr

The most frequently used dplyr verbs are:

  • filter() to keep rows;
  • select() to keep or reorder columns;
  • mutate() to create or modify columns;
  • arrange() to order rows;
  • group_by() to define groups; and
  • summarize() to reduce each group to summary values.

The %>% pipe passes the result on its left to the next function. Read the following pipeline from top to bottom as a sequence of steps.

game_results <- games %>%
  mutate(
    home_margin = home_score - away_score,
    home_win = home_margin > 0,
    turnover_margin = away_turnovers - home_turnovers
  ) %>%
  select(
    game_id,
    home_team,
    away_team,
    home_score,
    away_score,
    home_margin,
    home_win,
    turnover_margin
  )

5.2 Group and summarize

game_results %>%
  group_by(home_team) %>%
  summarize(
    games = n(),
    wins = sum(home_win),
    average_margin = mean(home_margin),
    .groups = "drop"
  ) %>%
  arrange(desc(average_margin))
# A tibble: 4 × 4
  home_team games  wins average_margin
  <chr>     <int> <int>          <dbl>
1 PHI           2     2             11
2 KC            2     1              7
3 BUF           2     1              2
4 SF            2     1              2

The .groups = "drop" argument returns an ungrouped result and prevents later operations from unexpectedly retaining the grouping.

5.3 Join related tables

A join connects tables through a key. Here, home_team in the game table corresponds to team in a lookup table.

team_lookup <- tribble(
  ~team, ~conference,
  "BUF", "AFC",
  "KC", "AFC",
  "PHI", "NFC",
  "SF", "NFC"
)

game_results %>%
  left_join(team_lookup, by = c("home_team" = "team")) %>%
  select(game_id, home_team, conference, home_margin)
# A tibble: 8 × 4
  game_id home_team conference home_margin
  <chr>   <chr>     <chr>            <dbl>
1 G1      BUF       AFC                  7
2 G2      KC        AFC                 -3
3 G3      PHI       NFC                  4
4 G4      SF        NFC                  7
5 G5      BUF       AFC                 -3
6 G6      KC        AFC                 17
7 G7      PHI       NFC                 18
8 G8      SF        NFC                 -3

Before a join, verify that the key is unique on the side expected to contribute one match. Duplicate keys can multiply rows.

7 Key takeaways

  • Choose a data structure that matches the shape and types of the data.
  • Distinguish element-wise multiplication * from matrix multiplication %*%.
  • Use t() for a transpose and solve() for an inverse or linear system.
  • Prefer solve(A, b) when the goal is to solve Ax=bAx=b.
  • Treat missing values and join keys explicitly.
  • Use %>% to express a sequence of data transformations in readable order.
