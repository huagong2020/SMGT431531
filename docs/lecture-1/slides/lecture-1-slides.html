R as a calculator

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

R follows the usual order of operations. Parentheses make the intended calculation explicit.

2 + 3 * 4
(2 + 3) * 4
sqrt(81)
log(exp(2))
choose(10, 2)

Use <- to assign a result to an object. Common arithmetic operators are +, -, *, /, ^, and %% for the remainder.

field_goals <- 4
extra_points <- 2
team_points <- 3 * field_goals + extra_points

Vectorized calculations and numerical comparison

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

Most R functions are vectorized: one operation is applied to every element of a vector.

yards <- c(4, -2, 12, 7, 0)

yards + 1
yards > 5
sum(yards)
mean(yards)

Computers store most decimal values approximately. Use all.equal() rather than exact equality when floating-point rounding may matter.

0.1 + 0.2 == 0.3
all.equal(0.1 + 0.2, 0.3)

Core data structures

Atomic vectors, coercion, and missing values

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

An atomic vector contains one basic type, such as logical, integer, double, character, or date-time.

completed_passes <- c(18L, 22L, 15L)
completion_rates <- c(0.64, 0.71, 0.58)
teams <- c("BUF", "KC", "PHI")
made_playoffs <- c(TRUE, TRUE, TRUE)

Combining incompatible types causes coercion to a common type. Missing values are represented by NA, and many summaries require an explicit decision about removing them.

c(1, TRUE, "BUF")
mean(c(62, 58, NA, 71), na.rm = TRUE)

Factors store categories and their level order

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

A factor stores categorical values together with their allowed levels. Set the order deliberately when it carries meaning.

game_phase <- factor(
  c("regular season", "postseason", "regular season"),
  levels = c("preseason", "regular season", "postseason")
)

game_phase
levels(game_phase)

The displayed labels are values, while the level order records how the categories should be organized.

Lists store nested or irregular objects

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

A list can contain objects of different types and sizes. Lists are common in JSON responses and model output.

player <- list(
  name = "Example Quarterback",
  position = "QB",
  weekly_yards = c(245, 310, 278),
  active = TRUE
)
  • player[["weekly_yards"]] extracts the object stored in one element.
  • player["weekly_yards"] returns a smaller, one-element list.
  • player$position extracts a named element and is convenient interactively.

Matrices and arrays preserve one atomic type

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

A matrix is a two-dimensional atomic vector. Every cell therefore has the same type.

player_stats <- matrix(
  c(245, 2, 310, 3, 278, 1),
  nrow = 3,
  byrow = TRUE,
  dimnames = list(
    week = paste0("Week ", 1:3),
    statistic = c("passing_yards", "touchdowns")
  )
)

An array generalizes a matrix to more than two dimensions. A tracking grid, for example, can have dimensions for x_position, y_position, and frame.

Data frames and tibbles are rectangular

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

Each row is an observation and each column is a variable. Columns may have different types, but every column must have the same number of rows.

games <- tibble(
  game_id = paste0("G", 1:8),
  home_team = c("BUF", "KC", "PHI", "SF", "BUF", "KC", "PHI", "SF"),
  away_team = c("MIA", "CIN", "DAL", "SEA", "NYJ", "LV", "NYG", "LAR"),
  home_score = c(31, 24, 21, 27, 17, 30, 28, 20),
  away_score = c(24, 27, 17, 20, 20, 13, 10, 23),
  home_turnovers = c(1, 2, 0, 1, 3, 0, 1, 2),
  away_turnovers = c(2, 1, 2, 2, 1, 3, 2, 1)
)

A tibble is a modern data frame with more readable printing and stricter behavior. The tutorial data are small teaching data, not official historical records.

Matrix calculations begin with dimensions

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

Matrix algebra supports linear regression, principal components, optimization, and many machine-learning algorithms. Let

A=[2113],b=[57]. A= \begin{bmatrix} 2 & 1\\ 1 & 3 \end{bmatrix}, \qquad b= \begin{bmatrix} 5\\ 7 \end{bmatrix}. 

A <- matrix(c(2, 1, 1, 3), nrow = 2, byrow = TRUE)
b <- c(5, 7)

Here, dim(A) is 2×22\times2. A matrix remains an atomic vector with a dimension attribute.

Transpose, identity, and determinant

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

The transpose A𝖳A^\mathsf{T} exchanges rows and columns. An identity matrix has ones on its diagonal and behaves like the number 1 in matrix multiplication.

t(A)
diag(2)
det(A)

For this matrix,

det⁡(A)=(2)(3)−(1)(1)=5. \det(A)=(2)(3)-(1)(1)=5.

Because the determinant is not zero, AA is invertible.

Element-wise multiplication is not matrix multiplication

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

A * A multiplies corresponding cells. A %*% A performs matrix multiplication.

A * A
A %*% A

For Am×nA_{m\times n} and Bn×pB_{n\times p}, the product ABAB has dimension m×pm\times p, and

(AB)ij=∑k=1naikbkj. (AB)_{ij}=\sum_{k=1}^{n}a_{ik}b_{kj}.

The inner dimensions must agree because each output cell is a row-by-column weighted sum.

The inverse and a linear system

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

The inverse satisfies AA−1=IAA^{-1}=I. For a 2×22\times2 matrix,

[abcd]−1=1ad−bc[d−b−ca]. \begin{bmatrix}a&b\\c&d\end{bmatrix}^{-1} =\frac{1}{ad-bc} \begin{bmatrix}d&-b\\-c&a\end{bmatrix}.

Therefore,

A−1=15[3−1−12]. A^{-1}=\frac{1}{5} \begin{bmatrix}3&-1\\-1&2\end{bmatrix}. 

A_inverse <- solve(A)
round(A %*% A_inverse, digits = 10)

Solve Ax=bAx=b without forming the inverse

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

Solving Ax=bAx=b gives x=A−1bx=A^{-1}b, but numerical work should use solve(A, b) directly.

x <- solve(A, b)
x
A %*% x

solve(A, b) is usually faster and more stable than calculating solve(A) %*% b. A singular matrix has no inverse, and a nearly singular matrix can produce unstable results.

Calculate an inverse when the inverse itself is the object of interest; solve the system directly when the goal is xx.

Matrix algebra connects directly to regression

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

For the linear model

y=Xβ+ε, y=X\beta+\varepsilon,

the ordinary least-squares estimate is

β̂=(X𝖳X)−1X𝖳y. \widehat{\beta}=(X^\mathsf{T}X)^{-1}X^\mathsf{T}y.

The first column of XX contains ones for the intercept. A second column can contain an illustrative turnover margin.

turnover_margin <- c(-2, -1, 0, 1, 2)
points_scored <- c(17, 20, 24, 27, 31)

X <- cbind(intercept = 1, turnover_margin = turnover_margin)
y <- points_scored

beta_hat <- solve(t(X) %*% X, t(X) %*% y)
beta_hat
coef(lm(points_scored ~ turnover_margin))

The calculations agree, although lm() uses a numerically safer matrix decomposition.

Core dplyr verbs express common transformations

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation
Verb Purpose
filter() Keep rows that satisfy conditions
select() Keep or reorder columns
mutate() Create or modify columns
arrange() Order rows
group_by() Define groups
summarize() Reduce each group to summary values

The %>% pipe passes the result on its left to the next function. Read a pipeline from top to bottom as a sequence of data-preparation steps.

A %>% pipeline makes the transformation sequence visible

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation
game_results <- games %>%
  mutate(
    home_margin = home_score - away_score,
    home_win = home_margin > 0,
    turnover_margin = away_turnovers - home_turnovers
  ) %>%
  select(
    game_id, home_team, away_team,
    home_score, away_score,
    home_margin, home_win, turnover_margin
  )

Positive turnover_margin means the home team committed fewer turnovers than the away team. A readable pipeline should make definitions like this explicit.

Filtering, arranging, grouping, and summarizing

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

Filtering keeps observations; arranging changes their order.

game_results %>%
  filter(abs(home_margin) <= 7) %>%
  arrange(abs(home_margin), game_id)

Grouping changes the unit at which a summary is calculated.

game_results %>%
  group_by(home_team) %>%
  summarize(
    games = n(),
    wins = sum(home_win),
    average_margin = mean(home_margin),
    .groups = "drop"
  )

.groups = "drop" prevents later operations from unexpectedly retaining the grouping.

A join requires a trustworthy key

SGMT 431 · Lecture 1.1 · R Foundations and Data Manipulation

A join connects tables through a key. Here, home_team corresponds to team in a lookup table.

team_lookup <- tribble(
  ~team, ~conference,
  "BUF", "AFC",
  "KC", "AFC",
  "PHI", "NFC",
  "SF", "NFC"
)

game_results %>%
  left_join(
    team_lookup,
    by = c("home_team" = "team")
  ) %>%
  select(game_id, home_team, conference, home_margin)

Before joining, verify that the key is unique on the side expected to contribute one match. Duplicate keys can multiply rows and silently change the unit of observation.

1.2 Scraping HTML Data from Websites

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

Inspect page structure, extract values with rvest, identify tables by schema, validate the result, and respect access rules.

Scrape only when HTML is the appropriate source

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

HTML scraping extracts information from a page designed primarily for people. First ask whether the same information is available through an official API, a downloadable file, or a maintained repository; those alternatives usually have a more stable structure.

A responsible workflow should:

  1. review terms of use, robots.txt, and attribution requirements;
  2. request only the pages needed;
  3. avoid rapid repeated requests and cache a permitted local copy;
  4. identify the provider and retrieval date; and
  5. never bypass authentication, restrictions, or technical controls.

Visibility in a browser does not automatically grant permission to collect, redistribute, or commercialize page content.

HTML represents a page as nested elements

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites
<article class="game-card" data-game-id="G01">
  <h2>Buffalo 21, Miami 14</h2>
  <a class="box-score" href="/games/G01">Box score</a>
</article>

In this example:

  • article, h2, and a are element names;
  • class, data-game-id, and href are attributes; and
  • Buffalo 21, Miami 14 is text.

A selector locates elements in this tree; an extraction function retrieves their text or attributes.

Begin with a reproducible local page

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

read_html() can read a local HTML file or a permitted web address. The tutorial begins with a local teaching page so parsing does not depend on network access.

page <- read_html("data/sample-standings.html")

page %>%
  html_element("h1") %>%
  html_text2()

page %>%
  html_elements("h2") %>%
  html_text2()

Use html_element() when one match is expected and html_elements() when several matches are expected.

CSS selectors describe which elements to find

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites
Selector Meaning
h2 Every <h2> element
.game-card Elements whose class includes game-card
#standings The element whose id is standings
[data-game-id] Elements containing the named attribute
.game-card h2 <h2> elements inside a game card
a.box-score <a> elements with class box-score

Prefer short selectors based on meaningful IDs, classes, and attributes rather than long paths tied to the visual layout.

game_cards <- page %>% html_elements(".game-card")

Extract text and attributes without losing row alignment

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

html_text2() extracts visible-style text with normalized spacing. html_attr() extracts an attribute.

featured_games <- tibble(
  game_id = game_cards %>%
    html_attr("data-game-id"),
  result = game_cards %>%
    html_element("h2") %>%
    html_text2(),
  status = game_cards %>%
    html_element(".status") %>%
    html_text2(),
  box_score_path = game_cards %>%
    html_element("a.box-score") %>%
    html_attr("href")
)

Compare the number of extracted values with the number of source elements. A missing expected child becomes NA, which helps keep rows aligned.

Selecting a table by position is fragile

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

html_table() converts an HTML table into a tibble, but a page may contain navigation, advertisements, standings, and unrelated statistics.

page_tables <- page %>%
  html_elements("table") %>%
  html_table(trim = TRUE)

length(page_tables)
lapply(page_tables, names)

The teaching page deliberately places an advertisement table before the standings table. Therefore, page_tables[[2]] depends on page position rather than the meaning of the data.

Select a table by the fields it must contain, not by where it happened to appear today.

Identify the standings table by its schema

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites
required_columns <- c(
  "Team", "W", "L", "Point differential"
)

is_standings_table <- vapply(
  page_tables,
  function(table) {
    all(required_columns %in% names(table))
  },
  logical(1)
)

Then select and clean the matching table.

standings <- page_tables[[which(is_standings_table)]] %>%
  rename(wins = W, losses = L) %>%
  mutate(
    wins = as.integer(wins),
    losses = as.integer(losses)
  )

The required-column test documents what the scraper expects from the page.

XPath handles relationships that are awkward in CSS

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

CSS selectors are usually simpler for straightforward scraping. XPath is useful when selection depends on a relationship or text contained deeper in the tree.

standings_with_xpath <- page %>%
  html_element(
    xpath = paste0(
      "//table[.//th[contains(., ",
      "'Point differential')]]"
    )
  ) %>%
  html_table(trim = TRUE)

The XPath selects the first table whose header cells include Point differential. Other patterns can locate all tables, elements with an attribute, link destinations, or HTML comments.

A reusable scraper states and checks its assumptions

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites
read_standings_table <- function(source) {
  tables <- read_html(source) %>%
    html_elements("table") %>%
    html_table(trim = TRUE)

  required <- c("Team", "W", "L", "Point differential")
  keep <- vapply(
    tables,
    function(table) all(required %in% names(table)),
    logical(1)
  )

  if (sum(keep) != 1) {
    stop("Expected exactly one standings table; found ",
         sum(keep), ".")
  }

  tables[[which(keep)]] %>%
    rename(
      wins = W,
      losses = L,
      point_differential = `Point differential`
    ) %>%
    mutate(
      wins = as.integer(wins),
      losses = as.integer(losses),
      point_differential = parse_number(as.character(point_differential))
    )
}

standings_checked <- read_standings_table(
    "data/sample-standings.html"
    )
}

The function fails with a useful message when the page no longer matches the expected structure.

A successful request can still return the wrong content

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

Validation must check assumptions that matter to the analysis.

stopifnot(
  nrow(standings_checked) == 4,
  !anyDuplicated(standings_checked$Team),
  all(standings_checked$wins >= 0),
  all(standings_checked$losses >= 0),
  all(standings_checked$wins + standings_checked$losses == 17)
)

Useful checks include expected columns, unique identifiers, plausible ranges, row counts, missingness, and comparison with a known value on the source page.

Scrapers fail for predictable reasons

SGMT 431 · Lecture 1.2 · Scraping HTML Data from Websites

A scraper may stop working because:

  • an ID, class, heading, or table schema changed;
  • the server returned consent, rate-limit, or access-denied content;
  • JavaScript creates the content after the initial HTML loads;
  • a table is stored inside an HTML comment;
  • repeated headers or merged cells alter parsed rows; or
  • the visible page is a presentation layer over an undocumented API.

rvest::read_html_live() can support permitted JavaScript-generated pages, but it adds dependencies and must not be used to bypass access controls. Prefer a documented API when one exists.

1.3 Working with JSON and APIs

SGMT 431 · Lecture 1.3 · Working with JSON and APIs

Map JSON to R structures, preserve nested relationships, build explicit HTTP requests, and handle failures responsibly.

APIs and HTML serve different primary audiences

SGMT 431 · Lecture 1.3 · Working with JSON and APIs

An API defines how software can request data or services. A web API commonly accepts an HTTP request and returns JSON.

Format Primary audience Structure Typical R tools
HTML People using a browser Elements, attributes, and text rvest, xml2
JSON Programs exchanging data Objects, arrays, names, and values jsonlite, httr2

When a documented API provides the required information, it is usually preferable to scraping a visual page. APIs can still change, limit requests, require authentication, or prohibit redistribution.

JSON types map to R imperfectly

SGMT 431 · Lecture 1.3 · Working with JSON and APIs
JSON value Example Common R representation
Number 34 or 0.625 Integer or double
String "BUF" Character
Boolean true Logical
Null null NULL or NA, depending on context
Array [3, 7, 0] Vector, list, or data frame
Object {"team":"BUF","score":34} Named list or data-frame columns

Objects and arrays can be nested to any depth. Do not assume that a response is already one rectangular table.

Create a tidy game table from flattened fields

Preserve the parent key when expanding a nested array

SGMT 431 · Lecture 1.3 · Working with JSON and APIs

Each game contains a drives array. In R, it becomes a list-column in which each row stores a small data frame.

drive_events <- lapply(seq_len(nrow(games)), function(i) {
  as_tibble(games$drives[[i]]) %>%
    mutate(
      game_id = games$game_id[[i]],
      .before = 1
    )
}) %>%
  bind_rows()

Adding game_id before combining the nested records preserves the relationship between each drive and its game. Discarding a list-column too early can remove information needed later.

An HTTP request has explicit components

An API request may contain:

  • a method such as GET;
  • a base URL and endpoint path;
  • query parameters after ?;
  • headers such as authentication or a user agent; and
  • an optional body, often with POST, PUT, or PATCH.

A reusable API function contains the complete workflow

SGMT 431 · Lecture 1.3 · Working with JSON and APIs

The tutorial function get_mlb_standings(season, date) places these steps together:

  1. construct the endpoint and query parameters;
  2. identify the teaching request with a user agent;
  3. retry temporary failures and perform the request;
  4. parse the response body as JSON;
  5. stop if no standings records were returned;
  6. preserve the season and division while combining teams; and
  7. stop if team identifiers are duplicated.

A reusable function should collect request construction, parsing, transformation, and validation—not only the successful path.

Keep authentication secrets outside the document

SGMT 431 · Lecture 1.3 · Working with JSON and APIs

Never type a key or token directly into a .qmd file or commit it to a repository. Store it in an environment variable.

api_key <- Sys.getenv("SPORTS_API_KEY")

if (api_key == "") {
  stop("SPORTS_API_KEY is not configured.")
}

authenticated_request <- request(
  "https://api.example.com/games"
) %>%
  req_headers(
    Authorization = paste("Bearer", api_key)
  )

Do not print request objects or headers when they may contain a secret.

Pagination, rate limits, and caching are part of the design

SGMT 431 · Lecture 1.3 · Working with JSON and APIs

Large APIs divide results into pages. Documentation determines whether pagination uses page numbers, offsets, cursors, or response links.

For reliable and respectful use:

  • request only the fields and dates needed;
  • obey rate limits and Retry-After headers;
  • retry only temporary failures;
  • save permitted raw responses with retrieval metadata;
  • avoid repeatedly downloading unchanged historical data; and
  • distinguish a valid empty result from an error response.

Stop according to the documented pagination rule, not an arbitrary loop count.

The R package is not necessarily the data source

SGMT 431 · Lecture 1.4 · Sports Data Sources and R Packages

An R package is software. It may download data from an official API, scrape a public website, retrieve prepared repository files, or combine sources.

upstream provider→API, website, or repository→R package→analysis table. \text{upstream provider} \longrightarrow \text{API, website, or repository} \longrightarrow \text{R package} \longrightarrow \text{analysis table}.

Saying only “the data came from baseballr” is incomplete when the function obtains records from the MLB Stats API. A responsible record identifies every important layer.

An R package does not grant rights that the upstream provider withholds.
