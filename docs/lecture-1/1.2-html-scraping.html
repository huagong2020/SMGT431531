1.2 Scraping HTML Data from Websites

Author

Hua Gong

1 Learning objectives

After completing this tutorial, you should be able to:

  1. describe the roles of HTML elements, attributes, and text;
  2. select elements with CSS selectors and XPath;
  3. extract text, attributes, links, and tables with rvest;
  4. identify a table by its schema instead of its page position;
  5. validate a scraped result before analysis; and
  6. explain the legal, ethical, and technical limits of web scraping.

2 When scraping is appropriate

HTML scraping extracts information from a page designed primarily for people. Before scraping, ask whether the same information is available through an official API, a downloadable file, or a maintained data repository. Those alternatives usually have a more stable structure.

A responsible workflow includes the following checks:

  1. Review the site’s terms of use, robots.txt, and attribution requirements.
  2. Request only the pages needed for the analysis.
  3. Avoid rapid or repeated requests; cache a permitted local copy.
  4. Identify the data provider and retrieval date.
  5. Do not attempt to bypass authentication, access restrictions, or technical controls.
Warning

A page being visible in a browser does not automatically grant permission to collect, redistribute, or commercialize its contents.

3 How HTML represents a page

HTML uses nested elements. An element normally has an opening tag, content, and a closing tag.

<article class="game-card" data-game-id="G01">
  <h2>Buffalo 21, Miami 14</h2>
  <a class="box-score" href="/games/G01">Box score</a>
</article>

In this example:

  • article, h2, and a are element names;
  • class, data-game-id, and href are attributes; and
  • Buffalo 21, Miami 14 is text.

4 Read a page

read_html() can read either a local HTML file or a permitted web address. We begin with the local teaching page included in this project so that the example remains reproducible.

page <- read_html("data/sample-standings.html")
page

[1] <head>\n<meta http-equiv="Content-Type" content="text/html; charset=UTF-8 ...
[2] <body>\n  <main><h1>Sample Football Results</h1>\n    <p class="updated"> ...

Use html_element() when one match is expected and html_elements() when several matches are expected.

page %>%
  html_element("h1") %>%
  html_text2()
[1] "Sample Football Results"
page %>%
  html_elements("h2") %>%
  html_text2()
[1] "Buffalo 21, Miami 14"       "Dallas 20, Philadelphia 27"

5 CSS selectors

A CSS selector describes the elements to find.

Selector Meaning
h2 Every <h2> element
.game-card Elements whose class includes game-card
#standings The element whose id is standings
[data-game-id] Elements containing the named attribute
.game-card h2 <h2> elements inside a game card
a.box-score <a> elements with class box-score

Browser developer tools can help identify candidate selectors. Prefer selectors based on meaningful IDs, classes, and attributes rather than long paths tied to the visual layout.

game_cards <- page %>%
  html_elements(".game-card")

length(game_cards)
[1] 2

6 Extract structured values

html_text2() extracts visible-style text with normalized spacing. html_attr() extracts an attribute.

featured_games <- tibble(
  game_id = game_cards %>%
    html_attr("data-game-id"),
  result = game_cards %>%
    html_element("h2") %>%
    html_text2(),
  status = game_cards %>%
    html_element(".status") %>%
    html_text2(),
  box_score_path = game_cards %>%
    html_element("a.box-score") %>%
    html_attr("href")
)

featured_games
# A tibble: 2 × 4
  game_id result                     status box_score_path
  <chr>   <chr>                      <chr>  <chr>         
1 G01     Buffalo 21, Miami 14       Final  /games/G01    
2 G02     Dallas 20, Philadelphia 27 Final  /games/G02

Always compare the number of extracted values with the number of source elements. If an expected child is absent, html_element() returns a missing element and the extracted value becomes NA, which helps keep rows aligned.

7 Extract tables

html_table() converts an HTML table into a tibble. A page may contain standings, navigation tables, advertisements, and unrelated statistics, so selecting the first or third table is fragile.

page_tables <- page %>%
  html_elements("table") %>%
  html_table(trim = TRUE)

length(page_tables)
[1] 2
lapply(page_tables, names)
[[1]]
[1] "Partner" "Message"

[[2]]
[1] "Team"               "W"                  "L"                 
[4] "Point differential"

The teaching page deliberately places an advertisement table before the standings table. Select the desired table by its required columns.

required_columns <- c("Team", "W", "L", "Point differential")

is_standings_table <- vapply(
  page_tables,
  function(table) all(required_columns %in% names(table)),
  logical(1)
)

is_standings_table
[1] FALSE  TRUE

Now extract and clean the matching table.

standings <- page_tables[[which(is_standings_table)]] %>%
  rename(
    wins = W,
    losses = L,
    point_differential = `Point differential`
  ) %>%
  mutate(
    wins = as.integer(wins),
    losses = as.integer(losses),
    point_differential = parse_number(as.character(point_differential))
  )

standings

parse_number() removes symbols such as a leading plus sign and returns a numeric value. Inspect the output before relying on automatic conversion.

8 XPath

XPath is another language for navigating an HTML tree. CSS selectors are usually easier for straightforward page scraping, while XPath is useful for relationships that are difficult to express with CSS.

The following XPath selects the first table whose header cells include the text Point differential:

standings_with_xpath <- page %>%
  html_element(xpath = "//table[.//th[contains(., 'Point differential')]]") %>%
  html_table(trim = TRUE)

standings_with_xpath
# A tibble: 4 × 4
  Team             W     L `Point differential`
  <chr>        <int> <int>                <int>
1 Baltimore       13     4                  203
2 Buffalo         11     6                  140
3 Dallas          12     5                  194
4 Philadelphia    11     6                    5

Common XPath patterns include:

XPath Meaning
//table Every table anywhere in the document
//article[@data-game-id] Articles containing a data-game-id attribute
//a/@href Every link destination attribute
//comment() HTML comment nodes

9 Write a reusable scraper

A function should express its assumptions and stop with a useful message when the page no longer matches them.

read_standings_table <- function(source) {
  tables <- read_html(source) %>%
    html_elements("table") %>%
    html_table(trim = TRUE)

  required <- c("Team", "W", "L", "Point differential")
  keep <- vapply(
    tables,
    function(table) all(required %in% names(table)),
    logical(1)
  )

  if (sum(keep) != 1) {
    stop(
      "Expected exactly one standings table; found ",
      sum(keep),
      "."
    )
  }

  tables[[which(keep)]] %>%
    rename(
      wins = W,
      losses = L,
      point_differential = `Point differential`
    ) %>%
    mutate(
      wins = as.integer(wins),
      losses = as.integer(losses),
      point_differential = parse_number(as.character(point_differential))
    )
}

standings_checked <- read_standings_table(
  "data/sample-standings.html"
)

standings_checked

10 Validate the result

A request can succeed while returning the wrong content. Check assumptions that matter to the analysis.

stopifnot(
  nrow(standings_checked) == 4,
  !anyDuplicated(standings_checked$Team),
  all(standings_checked$wins >= 0),
  all(standings_checked$losses >= 0),
  all(standings_checked$wins + standings_checked$losses == 17)
)

Useful checks include expected columns, unique identifiers, plausible ranges, row counts, missingness, and comparisons with a known value on the source page.

11 Move from a local page to a website

Once the parser works on a saved example, the same functions can read a permitted URL.

standings_url <- paste0(
  "https://en.wikipedia.org/wiki/",
  "2018_Major_League_Baseball_season"
)

live_page <- read_html(standings_url)

live_page %>%
  html_elements(".MLBStandingsTable") %>%
  html_table() %>%
  bind_rows()

Do not assume that selectors from the teaching page apply to another website. Inspect the new page, identify its schema, and write new validation rules.

12 Why scrapers fail

A scraper may stop working because:

  • an ID, class, heading, or table schema changed;
  • the server returned a consent page, rate-limit response, or access-denied page;
  • JavaScript creates the content after the initial HTML loads;
  • a table is stored inside an HTML comment;
  • repeated headers or merged cells change the parsed rows; or
  • the visible page is a presentation layer over an undocumented API.

For JavaScript-generated pages, rvest::read_html_live() can control a browser-backed session. This approach has more dependencies and should not be used to bypass access controls. If the page retrieves data from a documented API, use that API instead.

14 Key takeaways

  • Inspect the page structure before writing extraction code.
  • Prefer short, meaningful selectors tied to content rather than visual position.
  • Use html_elements() for repeated records and html_element() for one child per record.
  • Select tables by required fields, not by list position.
  • Validate every scraped result and expect the page structure to change.
  • Follow access rules and prefer an API or maintained download when available.
