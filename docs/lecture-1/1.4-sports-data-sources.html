1.4 Sports Data Sources and R Packages

Author

Hua Gong

1 Learning objectives

After completing this tutorial, you should be able to:

  1. distinguish an R package from its upstream data provider;
  2. compare official APIs, maintained repositories, package wrappers, and HTML scraping;
  3. identify widely used R packages for major sports;

2 The package is not necessarily the source

An R package is software. It may download data from an official API, scrape a public website, retrieve prepared files from a repository, or combine several sources.

The full data path is often:

upstream provider→API, website, or repository→R package→analysis table. \text{upstream provider} \longrightarrow \text{API, website, or repository} \longrightarrow \text{R package} \longrightarrow \text{analysis table}.

A responsible citation and provenance record should identify every important layer. Saying only “the data came from baseballr” is incomplete when the function actually obtains records from the MLB Stats API.

Important

An R package does not grant rights that the upstream provider withholds. Check the provider’s terms, licensing, attribution rules, and redistribution restrictions.

3 Four common acquisition methods

Method Strength Limitation Good use case
Official API or download Structured and documented by the provider May require a key, impose limits, or change versions Current schedules, standings, and official statistics
Maintained repository Fast access to large historical files; may offer versioned releases Refresh and transformation methods depend on maintainers Multi-season play-by-play modeling
R package wrapper Shorter code and consistent R-friendly output Adds a dependency and may hide upstream details Classroom work and repeatable data preparation
HTML scraping Can access information without an API Fragile and subject to site rules A permitted field unavailable elsewhere

The categories overlap. For example, nflreadr is an R package that downloads prepared season files from nflverse repositories.

4 Package directory

Package capabilities and upstream access can change. Review the current function documentation before beginning a project.

Package Sport or scope Typical access and data Documentation
nflreadr NFL nflverse play-by-play, schedules, rosters, players, and statistics Official documentation
baseballr MLB, MiLB, and college baseball MLB Stats API, Statcast, and several baseball websites and repositories Official documentation

wehoop Women’s basketball WNBA and women’s college basketball play-by-play and box scores Official documentation
fastRhockey Hockey NHL and PWHL data from public web APIs and maintained files Official documentation

The NFL ecosystem is maintained as nflverse and is separate from the core sportsdataverse meta-package.

5 Install packages deliberately

Install a package once in the R console. Load only the packages needed for the analysis.

install.packages("nflreadr")
install.packages("baseballr")
install.packages("hoopR")

# Install the core SportsDataverse packages together if needed.
install.packages("sportsdataverse")

Namespace notation identifies the package that supplies a function without attaching every function in that package.

nfl_plays <- nflreadr::load_pbp(seasons = 2023)

6 Example 1: NFL play-by-play with nflreadr

load_pbp() downloads complete play-by-play seasons from the nflverse data repository. The files are large, so request only the seasons required for the research design.

nfl_plays_2023 <- nflreadr::load_pbp(
  seasons = 2023,
  file_type = "rds"
)

nfl_analysis_fields <- nfl_plays_2023 %>%
  select(
    game_id,
    play_id,
    season,
    week,
    posteam,
    defteam,
    play_type,
    yards_gained,
    touchdown,
    home_wp,
    home_team,
    away_team
  )

nfl_analysis_fields %>%
  slice_head(n = 10)

Do not overwrite the raw object while exploring. First retain the identifying fields and variables needed to interpret the outcome.

6.1 Inspect the data dictionary

Variable names such as home_wp, wp, and vegas_wp may look similar but have different definitions. Use the package data dictionary rather than guessing from a name.

nflreadr::dictionary_pbp %>%
  filter(Field %in% c("home_wp", "wp", "vegas_wp")) %>%
  select(Field, Description)

Before modeling, check:

  • the unit of observation;
  • the exact outcome definition;
  • whether a field is known at prediction time;
  • whether a value was calculated after the event;
  • the missing-value convention; and
  • whether team and player identifiers are stable across seasons.

7 Example 2: MLB standings with baseballr

baseballr::mlb_standings() wraps the MLB standings endpoint introduced directly in Tutorial 1.3.

mlb_standings_2019 <- baseballr::mlb_standings(
  season = 2019,
  date = "2019-09-29",
  standings_type = "regularSeason",
  league_id = c(103, 104)
)

mlb_standings_2019 %>%
  select(
    team = team_records_team_name,
    wins = team_records_wins,
    losses = team_records_losses,
    runs_scored = team_records_runs_scored,
    runs_allowed = team_records_runs_allowed,
    run_differential = team_records_run_differential
  ) %>%
  arrange(desc(wins))

The package wrapper is concise and returns a tibble. A direct API request makes request parameters, HTTP handling, and JSON structure more visible. Choose the level of abstraction that fits the research and teaching objective.

8 Example 3: Basketball loaders

SportsDataverse packages use similar naming for many prepared season files.

# Men's professional basketball
nba_pbp <- hoopR::load_nba_pbp(seasons = 2023)

# Women's professional basketball
wnba_pbp <- wehoop::load_wnba_pbp(seasons = 2023)

# Men's college basketball
mbb_pbp <- hoopR::load_mbb_pbp(seasons = 2023)

# Women's college basketball
wbb_pbp <- wehoop::load_wbb_pbp(seasons = 2023)

Do not assume that the same season label means the same calendar period in every sport. Confirm how the package defines a season and whether postseason games are included.
