2.7 Hyperparameter Tuning and Feature Importance

Selecting models and explaining what they learned

Author

Hua Gong

1 Learning objectives

After completing this tutorial, you should be able to:

  1. distinguish fitted parameters from hyperparameters;
  2. design grouped, temporally honest model tuning;
  3. tune random-forest and XGBoost parameters in R;
  4. calculate impurity, permutation, and gain importance;
  5. explain local SHAP values and global SHAP summaries; and
  6. recognize when an importance ranking is misleading.

2 Parameters versus hyperparameters

A fitted parameter is learned inside a model fit. Examples include a logistic coefficient, a tree’s split threshold, and an XGBoost leaf weight. A hyperparameter controls the learning procedure and is selected outside that fit. Examples include mtry, tree depth, learning rate, and minimum leaf size.

Let θ∈Θ\theta\in\Theta denote a candidate hyperparameter configuration. With KK validation resamples, a general tuning rule is

θ̂=arg⁡minθ∈Θ1K∑k=1KLk(θ), \hat\theta =\arg\min_{\theta\in\Theta} \frac{1}{K}\sum_{k=1}^{K} L_k(\theta),

where Lk(θ)L_k(\theta) is a validation loss such as log loss. The objective is not to find parameters that minimize training loss. It is to find a learning procedure that performs well on games not used to fit it.

3 The resampling design matters more than the search algorithm

The course workflow uses three levels:

  1. Analysis games: fit each candidate model.
  2. Validation games: compare hyperparameters and select the number of boosting rounds.
  3. 2023 test games: evaluate the locked workflow once.

All states from one game must remain together. Otherwise, a model can be trained using some states from a game and evaluated using other states with the same final outcome.

For a more extensive project, replace the one grouped validation split with grouped KK-fold cross-validation inside 2022. The 2023 season remains outside every tuning calculation.

4 Choose the tuning objective before searching

For win probability, use a proper probability score:

  • log loss when confident errors should receive a strong penalty;
  • Brier score when squared probability error is the primary concern; and
  • calibration diagnostics as a required secondary check.

Accuracy should not be the main tuning criterion because it discards the difference between probabilities such as .51 and .99.

5 Tune a random forest

The following small grid varies the number of candidate predictors and the terminal-node size. Every candidate receives the same 250-tree computational budget and the same validation games.

forest_formula <- home_win_factor ~
  game_seconds_remaining + home_score_diff + home_possession +
  down + ydstogo + yardline_100 + home_timeouts + away_timeouts

forest_grid <- expand.grid(
  mtry = c(2, 4),
  min_node_size = c(25, 75),
  KEEP.OUT.ATTRS = FALSE
)

forest_tuning <- lapply(seq_len(nrow(forest_grid)), function(i) {
  candidate <- ranger(
    forest_formula,
    data = analysis_data,
    probability = TRUE,
    num.trees = 250,
    mtry = forest_grid$mtry[i],
    min.node.size = forest_grid$min_node_size[i],
    seed = 431 + i
  )

  probability <- predict(
    candidate,
    data = validation_data
  )$predictions[, "win"]

  probability_metrics(
    validation_data$home_win,
    probability,
    "random forest"
  ) %>%
    mutate(
      mtry = forest_grid$mtry[i],
      min_node_size = forest_grid$min_node_size[i],
      oob_brier = candidate$prediction.error
    )
}) %>%
  bind_rows() %>%
  arrange(log_loss)

The grid is intentionally small enough to teach transparently. A larger search is not automatically better: repeated experimentation on one validation set gradually overfits that validation set.

6 Tune XGBoost with early stopping

Learning rate and tree depth interact with the number of rounds. Each candidate below receives a large round limit; early stopping chooses its effective number of trees.

analysis_matrix <- model_matrix(analysis_data)
validation_matrix <- model_matrix(validation_data)

xgb_analysis <- xgb.DMatrix(
  analysis_matrix,
  label = analysis_data$home_win
)
xgb_validation <- xgb.DMatrix(
  validation_matrix,
  label = validation_data$home_win
)

xgb_grid <- expand.grid(
  eta = c(0.03, 0.08),
  max_depth = c(2, 4),
  KEEP.OUT.ATTRS = FALSE
)

xgb_tuning <- lapply(seq_len(nrow(xgb_grid)), function(i) {
  set.seed(431 + i)
  candidate <- xgb.train(
    params = list(
      objective = "binary:logistic",
      eval_metric = "logloss",
      eta = xgb_grid$eta[i],
      max_depth = as.integer(xgb_grid$max_depth[i]),
      min_child_weight = 20,
      subsample = 0.80,
      colsample_bytree = 0.80,
      lambda = 1
    ),
    data = xgb_analysis,
    nrounds = 400,
    watchlist = list(validation = xgb_validation),
    early_stopping_rounds = 25,
    verbose = 0
  )

  probability <- predict(candidate, validation_matrix)

  probability_metrics(
    validation_data$home_win,
    probability,
    "XGBoost"
  ) %>%
    mutate(
      eta = xgb_grid$eta[i],
      max_depth = xgb_grid$max_depth[i],
      best_iteration = candidate$best_iteration
    )
}) %>%
  bind_rows() %>%
  arrange(log_loss)

7 A defensible search sequence

A practical order is:

  1. establish a logistic baseline;
  2. choose a primary probability metric;
  3. tune tree structure with a moderate learning rate;
  4. tune row and feature sampling;
  5. tune regularization;
  6. lower the learning rate and use early stopping for the final round count; and
  7. evaluate calibration before locking the workflow.

Random search is often more efficient than a large rectangular grid when many parameters are active. Bayesian optimization can reduce the number of expensive fits further. Neither method repairs an invalid resampling design.

8 Mean decrease impurity

For feature jj, mean decrease impurity adds the weighted Gini improvements from every split using jj:

IMDI(j)=1B∑b=1B∑s∈Tb:v(s)=jnsnΔIs. I_{MDI}(j)=\frac{1}{B}\sum_{b=1}^{B} \sum_{s\in T_b:v(s)=j} \frac{n_s}{n}\Delta I_s.

Suppose a root node contains 60 wins and 40 losses. Its Gini impurity is

2(.60)(.40)=.48. 2(.60)(.40)=.48.

A split creates a 40-state child with win rate .90 and a 60-state child with win rate .40. The weighted child impurity is

40100{2(.90)(.10)}+60100{2(.40)(.60)}=.36. \frac{40}{100}\{2(.90)(.10)\} +\frac{60}{100}\{2(.40)(.60)\} =.36.

The root split contributes .48−.36=.12.48-.36=.12 to the feature’s weighted impurity reduction. Deeper splits are multiplied by the fraction of training observations reaching their parent node.

9 Validation permutation importance

Let L0L_0 be validation loss from the original data and LjrpermL_{jr}^{perm} be the loss after shuffling feature jj in repetition rr. Repeated permutation importance is

Iperm(j)=1R∑r=1R(Ljrperm−L0). I_{perm}(j)=\frac{1}{R}\sum_{r=1}^{R} \left(L_{jr}^{perm}-L_0\right).

This definition can use the same log-loss scale for logistic regression, random forests, and boosting.

forest_probability <- predict(
  tuned_forest,
  data = validation_data
)$predictions[, "win"]

baseline_loss <- log_loss(
  validation_data$home_win,
  forest_probability
)

set.seed(431)
permutation_importance <- lapply(wp_predictors, function(feature_name) {
  repeated_losses <- replicate(5, {
    permuted_data <- validation_data
    permuted_data[[feature_name]] <- sample(
      permuted_data[[feature_name]]
    )
    permuted_probability <- predict(
      tuned_forest,
      data = permuted_data
    )$predictions[, "win"]
    log_loss(validation_data$home_win, permuted_probability)
  })

  tibble(
    feature = feature_name,
    importance = mean(repeated_losses) - baseline_loss,
    permutation_sd = sd(repeated_losses)
  )
}) %>%
  bind_rows() %>%
  arrange(desc(importance))

ggplot(
  permutation_importance,
  aes(x = importance, y = reorder(feature, importance))
) +
  geom_col(fill = "#03a9e6") +
  geom_errorbar(
    aes(
      xmin = importance - permutation_sd,
      xmax = importance + permutation_sd
    ),
    width = 0.20
  ) +
  labs(
    title = "Random-forest validation permutation importance",
    subtitle = "Increase in 2022 validation log loss; larger is more important",
    x = "Mean increase in log loss",
    y = NULL
  ) +
  theme_minimal()

A negative value means the shuffled feature happened to improve validation loss. This can arise from sampling variation, overfitting, or a weak feature. It is not evidence that the feature has a protective causal effect.

10 XGBoost gain, cover, and frequency

For a retained XGBoost split ss, regularized gain is

Gain⁡s=12[GL2HL+λ+GR2HR+λ−(GL+GR)2HL+HR+λ]−γ. \operatorname{Gain}_s =\frac{1}{2}\left[ \frac{G_L^2}{H_L+\lambda} +\frac{G_R^2}{H_R+\lambda} -\frac{(G_L+G_R)^2}{H_L+H_R+\lambda} \right]-\gamma.

For feature jj, XGBoost sums gain over splits using jj and normalizes across features. Frequency counts how often the feature is used. Cover aggregates the Hessian mass affected by its splits.

xgb_importance <- xgb.importance(

  model = tuned_xgb
)

Gain is tied to the model’s training objective, while permutation importance is tied to a chosen evaluation data set and metric. Their rankings can legitimately differ.

11 SHAP values: local contributions

SHAP values decompose one prediction on the model’s raw output scale:

F(x)=ϕ0+∑j=1pϕj(x), F(x)=\phi_0+\sum_{j=1}^{p}\phi_j(x),

where ϕ0\phi_0 is the expected model output and ϕj(x)\phi_j(x) is feature jj’s contribution for state xx. For binary XGBoost, the raw output is log odds; applying the logistic function converts the sum to probability.

A common global summary is

ISHAP(j)=1n∑i=1n|ϕj(xi)|. I_{SHAP}(j)=\frac{1}{n}\sum_{i=1}^{n}|\phi_j(x_i)|.

Unlike impurity or gain, SHAP can show whether a feature pushes a particular prediction up or down. The global mean absolute value removes direction and still does not establish causality. SHAP results also depend on how feature dependence is handled.

11.1 Calculate SHAP values in R

XGBoost computes exact tree SHAP values natively. Passing predcontrib = TRUE returns one contribution per feature plus a BIAS column holding ϕ0\phi_0.

shap_matrix <- predict(

  validation_matrix,
  predcontrib = TRUE
)

12 Importance methods compared

Method Data used Quantity calculated Direction? Main caution
Mean decrease impurity Training data Weighted split-impurity reduction No Favors variables with many candidate splits
XGBoost/LightGBM gain Training data Regularized objective improvement No Divides credit among correlated variables
Permutation OOB, validation, or test-like data Increase in a selected prediction loss No Unrealistic shuffles and correlated features
CatBoost PredictionValuesChange Model leaf structure and leaf weights Average prediction change across feature-dependent leaf pairs No Model-specific scale
SHAP Selected explanation data Additive contribution to each prediction Yes, locally Dependence assumptions and computation

Equivalent library calls include:

# LightGBM: gain and split counts
lgb.importance(lgb_fit, percentage = TRUE)

# CatBoost: default PredictionValuesChange for this classification model
catboost.get_feature_importance(
  cat_fit,
  pool = cat_validation,
  type = "FeatureImportance"
)

13 Rules for responsible interpretation

  1. State the exact importance definition and data set.
  2. Calculate importance on held-out or OOB data when the question concerns generalization.
  3. Repeat permutations and report variability.
  4. Examine groups of correlated features, not only isolated columns.
  5. Use partial dependence, accumulated local effects, or SHAP when direction matters.
  6. Never translate predictive importance directly into causal impact.

14 Practice questions

  1. Why must every state from an NFL game remain in the same resample?
  2. If baseline log loss is .54 and permuting home_score_diff produces .63, what is its permutation importance?
  3. Why can a continuous predictor receive inflated impurity importance?
  4. A feature has high split frequency but low gain. What does that mean?
  5. Why should eta and nrounds be tuned together?
  6. What extra information does a local SHAP value provide compared with global gain importance?
TipShow answers
  1. States from the same game share an outcome and much of their context. Splitting them across training and validation leaks game-specific information and makes validation performance optimistic.
  2. .63−.54=.09.63-.54=.09.
  3. A continuous predictor offers many possible thresholds. Searching more candidates creates more opportunities to find an impurity reduction caused partly by noise.
  4. The feature is used in many splits, but those splits produce only small improvements in the training objective.
  5. A smaller learning rate makes each tree’s update smaller, so more rounds are normally required. Tuning one while holding the other at an arbitrary value can make a good configuration appear to underfit.
  6. A local SHAP value reports the direction and magnitude of the feature’s contribution to one prediction on the model-output scale. Global gain only reports accumulated split improvement and has no per-state direction.

15 Key takeaways

  • Fitted parameters are learned inside a fit; hyperparameters are chosen outside it using held-out games.
  • The resampling design matters more than the search algorithm, and no search repairs an invalid split.
  • Tune on a proper scoring rule, never on accuracy.
  • Impurity, gain, permutation, and SHAP answer different questions on different data; always state which you used.
  • SHAP adds a direction to each individual prediction, but no importance measure establishes causality.
