2.3 Bagging and Random Forests

Author

Hua Gong

1 Learning objectives

After completing this tutorial, you should be able to:

  1. explain bootstrap aggregation;
  2. calculate an ensemble probability;
  3. derive why averaging correlated trees has a variance limit;
  4. describe the random-forest algorithm step by step;
  5. interpret out-of-bag probability estimates;
  6. explain impurity and permutation feature importance; and
  7. fit, tune, and compare bagged trees and random forests in R.

2 Why average trees?

A single deep tree has low bias but high variance. Bagging reduces variance by fitting trees to different bootstrap samples and averaging their predictions.

For BB fitted trees,

p̂bag(x)=1B∑b=1Bp̂b(x). \hat p_{bag}(x)=\frac{1}{B}\sum_{b=1}^{B}\hat p_b(x).

2.1 Numerical example

Suppose five bootstrap trees produce home-win probabilities

.60,.75,.66,.71,.58. .60,\ .75,\ .66,\ .71,\ .58.

The bagged estimate is

tree_probabilities <- c(0.60, 0.75, 0.66, 0.71, 0.58)
mean(tree_probabilities)
[1] 0.66

Individual trees disagree, but the average is more stable.

3 Bootstrap samples

A bootstrap sample contains nn observations drawn with replacement from nn training observations. Some observations appear multiple times and approximately 36.8% are omitted from a particular sample.

For one specific observation, the probability of not being selected in one draw is 1−1/n1-1/n. The probability of being omitted from all nn draws is

(1−1n)n→e−1≈.368. \left(1-\frac{1}{n}\right)^n \longrightarrow e^{-1}\approx .368.

Thus, each bootstrap tree is fitted with about 63.2% of the distinct training observations, although the bootstrap sample still contains nn rows because some rows are repeated.

The omitted observations are called out-of-bag observations. They can evaluate each tree without creating a separate validation set.

4.1 Vote share is not a probability

predict() on a bagged classifier can return two very different quantities, and the difference matters more than any tuning parameter in this tutorial.

  • aggregation = "majority", the ipred default, returns the fraction of trees that voted for each class. When every tree agrees, the reported value is exactly 0 or 1.
  • aggregation = "average" averages the trees’ leaf probabilities. This is the ensemble probability p̂bag(x)\hat p_{bag}(x) defined above.
bagged_votes <- predict(
  bagged_fit,
  newdata = validation_data,
  type = "prob",
  aggregation = "majority"
)[, "win"]

bagged_probability <- predict(
  bagged_fit,
  newdata = validation_data,
  type = "prob",
  aggregation = "average"
)[, "win"]

tibble(
  aggregation = c("majority (vote share)", "average (leaf probabilities)"),
  exactly_0_or_1 = c(
    mean(bagged_votes %in% c(0, 1)),
    mean(bagged_probability %in% c(0, 1))
  ),
  distinct_values = c(
    dplyr::n_distinct(bagged_votes),
    dplyr::n_distinct(bagged_probability)
  )
)

A unanimous vote is not certainty; it only means the bootstrap trees agreed. A 0 or 1 report is a claim that the outcome is impossible, and log loss treats it as such. Compare the two on the same games.

bind_rows(
  probability_metrics(
    validation_data$home_win,
    bagged_votes,
    model = "Bagged trees (majority vote share)"
  ),
  probability_metrics(
    validation_data$home_win,
    bagged_probability,
    model = "Bagged trees (averaged probabilities)"
  )
)
# A tibble: 2 × 4
  model                                 brier log_loss accuracy
  <chr>                                 <dbl>    <dbl>    <dbl>
1 Bagged trees (majority vote share)    0.203    0.735    0.690
2 Bagged trees (averaged probabilities) 0.189    0.554    0.695

The Brier scores are similar because squared error is bounded. Log loss is not bounded, so the unanimous states dominate it. Always confirm which quantity a classification package returns before treating its output as a probability.

Tip

This is one reason the course uses ranger rather than randomForest for forests. Setting probability = TRUE builds a probability forest, which averages the trees’ leaf probabilities rather than counting their votes. randomForest::predict(type = "prob") reports vote shares and offers no averaging option at all.

5 From bagging to random forests

Bootstrap trees can remain highly correlated because strong predictors—especially score difference and time remaining—are repeatedly selected near the top. A random forest adds random feature selection: at each split, only mtry predictors are eligible.

If individual trees have variance σ2\sigma^2 and average pairwise correlation ρ\rho, the variance of an average of BB trees is approximately

ρσ2+1−ρBσ2. \rho\sigma^2+\frac{1-\rho}{B}\sigma^2.

Increasing BB reduces the second term. Random feature selection aims to reduce ρ\rho.

The equation also explains an important limit. As B→∞B\rightarrow\infty,

Var⁡{p̂RF(x)}→ρσ2. \operatorname{Var}\{\hat p_{RF}(x)\}\longrightarrow \rho\sigma^2.

Adding trees averages away the independent portion of tree noise, but it cannot eliminate the shared error created by highly correlated trees. The mtry mechanism deliberately weakens individual trees when doing so lowers their correlation enough to improve the ensemble.

6 The random-forest algorithm

For b=1,…,Bb=1,\ldots,B:

  1. Draw a bootstrap sample of the training games or observations.
  2. Grow an unpruned tree on that sample.
  3. At each node, draw mm of the pp predictors, where mm is mtry.
  4. Search for the best split using only those mm candidates.
  5. Continue until a node-size or depth rule stops growth.

For a new state xx, tree bb produces a leaf probability p̂b(x)\hat p_b(x). The forest probability is

p̂RF(x)=1B∑b=1Bp̂b(x). \hat p_{RF}(x)=\frac{1}{B}\sum_{b=1}^{B}\hat p_b(x).

Classification software may alternatively report a majority vote, but a win-probability application should retain the averaged probability.

probability = TRUE is the argument that matters. Without it ranger grows a classification forest and reports votes; with it, every tree estimates leaf probabilities and the forest averages them.

Note what the printed summary reports as its out-of-bag error: a Brier score, not a misclassification rate. For a probability forest ranger scores itself with a proper scoring rule, which is exactly the criterion Tutorial 2.6 argues for. Set seed inside the call — ranger uses its own random number stream, so a preceding set.seed() does not make it reproducible.

The reported out-of-bag error is based on predictions from trees for which each training observation was not included in the bootstrap sample.

Let ℬiOOB\mathcal B_i^{OOB} be the set of trees for which observation ii was out of bag. Its OOB probability is

p̂iOOB=1|ℬiOOB|∑b∈ℬiOOBp̂b(xi). \hat p_i^{OOB} =\frac{1}{|\mathcal B_i^{OOB}|} \sum_{b\in\mathcal B_i^{OOB}}\hat p_b(x_i).

Because tree bb did not use observation ii when it was trained, this prediction is internally held out. For repeated game states, game-level resampling remains preferable when the software supports it: ordinary row-level OOB sampling can still place other states from the same game in a tree’s bootstrap sample.

Out-of-bag error is also the cheapest way to see how many trees are enough. Refit at a few sizes and watch the curve flatten.

tree_count_curve <- lapply(c(25, 50, 100, 200, 400), function(number_of_trees) {

9 How random-forest importance is calculated

Two common importance measures answer different questions.

For mean decrease impurity, every split using feature jj contributes its weighted impurity reduction. A forest-level score is

IMDI(j)=1B∑b=1B∑s∈Tb:v(s)=jnsnΔIs, I_{MDI}(j)=\frac{1}{B}\sum_{b=1}^{B} \sum_{s\in T_b:\,v(s)=j} \frac{n_s}{n}\Delta I_s,

where v(s)v(s) is the feature used at split ss, ns/nn_s/n weights a split by the fraction of training observations reaching it, and ΔIs\Delta I_s is its Gini decrease. The score is fast but can favor continuous or high-cardinality predictors because they offer more candidate splits.

Permutation importance first calculates a baseline loss. It then shuffles feature jj, breaks its association with the outcome and other features, and recalculates loss:

Iperm(j)=L{y,p̂(Xjperm)}−L{y,p̂(X)}. I_{perm}(j)=L\{y,\hat p(X_j^{perm})\} -L\{y,\hat p(X)\}.

If validation log loss increases from .52 to .60 after permuting score difference, its importance is .60−.52=.08.60-.52=.08. Repeating the shuffle estimates Monte Carlo variability. Correlated predictors can substitute for one another, so either one’s marginal permutation importance may appear small even when the pair is essential.

Because the forest was fitted with importance = "permutation", ranger stores an out-of-bag permutation score for each predictor. For a probability model, Tutorial 2.7 also calculates validation-set permutation importance using log loss directly.

10 Parameters that control a random forest

Parameter What it controls Main tradeoff
num.trees Number of bootstrap trees BB More stability versus more computation
mtry Candidate predictors at each split Tree strength versus tree correlation
min.node.size Minimum terminal-node size Local flexibility versus smoother probabilities
max.depth Maximum depth of any tree Interaction complexity versus variance
sample.fraction Rows or games available to each tree Diversity versus information per tree

num.trees is usually increased until OOB or validation loss stabilizes. The other parameters should be selected with grouped validation games. The tuning curve can be flat, so prefer a simpler setting when its performance is practically indistinguishable from the minimum. Tutorial 2.7 provides runnable grids for mtry and nodesize.

11 Bagging versus random forest

Feature Bagging Random forest
Bootstrap observations Yes Yes
Random predictors at each split No Yes
Primary goal Reduce tree variance Reduce variance and tree correlation
Built-in out-of-bag evaluation Common Common
Probability calibration guaranteed No No

2. Adding trees averages additional noisy estimates and stabilizes the ensemble. It does not make individual trees more complex. Performance generally approaches a limit, although computation continues to increase.

13 Key takeaways

  • Bagging reduces the variance of unstable trees.
  • Random forests also reduce correlation by sampling predictors at each split.
  • Out-of-bag predictions provide efficient internal evaluation.
  • A vote share is not a probability. Check what predict() returns before scoring it.
  • Ensemble probabilities still require held-out validation and calibration checks.
