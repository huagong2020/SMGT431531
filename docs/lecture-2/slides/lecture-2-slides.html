2.1 NFL Win Probability and a Logistic Baseline

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

Define a leakage-free prediction problem and establish a probability benchmark.

Frame the prediction problem

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

Permissible predictors at state tt include:

  • score difference and seconds remaining;
  • possession, field position, down, and yards to go;
  • home and away timeouts.

Final margin, the next scoring event, and postgame summaries are leakage because they are unknown at state tt.

Avoid leakage and preserve chronology

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

Data leakage happens when the model gets access, directly or indirectly, to information that would not actually be available at the moment you want to make the prediction.

  • Do not use variables that would be unavailable at prediction time. Examples include the final score and season ratings calculated with future games.
  • Do not split training and validation by state. Do it by game. If states from one game appear in both training and validation data, the validation set is not independent.

𝒟development={g:season(g)=2022},𝒟test={g:season(g)=2023}. \mathcal D_{\text{development}} =\{g:\text{season}(g)= 2022\}, \qquad \mathcal D_{\text{test}} =\{g:\text{season}(g)=2023\}.

Use 2022 for development and reserve 2023 as the final test season. Within 2022, assign complete games to either the training or validation sample.

Logistic regression

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

Let

ηi=β0+β1xi1+⋯+βpxip. \eta_i=\beta_0+\beta_1x_{i1}+\cdots+\beta_px_{ip}.

where ii represents a play in a game and pp denotes a predictor.

The logit is linear:

log⁡(pi1−pi)=ηi, \log\left(\frac{p_i}{1-p_i}\right)=\eta_i,

and the inverse logit maps any real number to a probability:

pi=σ(ηi)=11+e−ηi. p_i=\sigma(\eta_i)=\frac{1}{1+e^{-\eta_i}}.

Interpret coefficients on the odds scale

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

A one-unit increase in xjx_j changes log odds by βj\beta_j and multiplies odds by

p(xj+1)/(1−p(xj+1))p(xj)/(1−p(xj))=eβj. \frac{p(x_j+1)/(1-p(x_j+1))}{p(x_j)/(1-p(x_j))}=e^{\beta_j}.

If βscore diff=0.19\beta_{\text{score diff}}=0.19, one additional point multiplies home-win odds by

e0.19=1.209, e^{0.19}=1.209,

holding all other predictors fixed.

Convert one logit into a probability

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

Suppose a game state produces η=0.80\eta=0.80. Then

p̂=11+e−0.80=0.690. \hat p=\frac{1}{1+e^{-0.80}}=0.690. 

eta <- 0.80
1 / (1 + exp(-eta))

The model assigns a 69.0% home-win probability—not a guaranteed home win.

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

The interaction allows the effect of score difference to change as the game clock changes.

# run logistic regression

    home_possession + down + ydstogo + yardline_100 +
    home_timeouts + away_timeouts,
  data = analysis_data,

Proper scoring rules judge the whole probability

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

To evaluate the logistic regression performance, we first predict win probabilities on validation set. Then we calcuate Binary log loss and Brier score based on predicted probabilities. Both are lower when probabilities are better.

# predict win probability on validation set
validation_probability <- predict(
  logistic_fit,
  newdata = validation_data,
  type = "response"
)

Binary log loss is

LogLoss⁡=−1n∑i=1n[yilog(p̂i)+(1−yi)log(1−p̂i)]. \operatorname{LogLoss} =-\frac{1}{n}\sum_{i=1}^{n} \left[y_i\log(\hat p_i)+(1-y_i)\log(1-\hat p_i)\right].

The Brier score is

Brier⁡=1n∑i=1n(yi−p̂i)2. \operatorname{Brier}=\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat p_i)^2.

A confident error is expensive

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

For one home win, y=1y=1:

Prediction Log loss −log⁡(p)-\log(p) Brier (1−p)2(1-p)^2
.90 .105 .010
.60 .511 .160
.10 2.303 .810

Log loss strongly penalizes confident wrong predictions; Brier score has a bounded quadratic penalty.

Model calibration

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

A forecast is calibrated when states assigned probability pp lead to home wins approximately pp% of the time. For example, do we observe states assigned probability 0.70 lead to home wins approximately 70% of the time. Formally, we have

P{Y=1∣p̂(X)=p}=pfor every p. P\{Y=1\mid \hat p(X)=p\}=p \qquad \text{for every } p.

It conditions on what the model said — does the number mean what it claims?

In win probability the number is the product: broadcast graphics, fourth-down models, position sizing. No downstream threshold repairs a wrong 90%.

Calibration plot

SGMT 431 · Lecture 2.1 · NFL Win Probability and a Logistic Baseline

Each point is a bin of states with similar predictions. The horizontal position is the average forecast in that bin; the vertical position is the fraction that actually ended in a home win. Perfect calibration puts every point on the 45-degree line.

2.2 Classification and Regression Trees (CART)

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

Build conditional rules by repeatedly choosing the split that most reduces error.

A tree is a set of yes/no questions

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

Each internal node asks one question about one predictor. Each leaf is a terminal region holding one constant prediction.

Walk one path aloud: score differential below zero, then under ten minutes left, therefore region R1. Ask the class what makes R1 a region rather than just a rule — the two conditions together carve out a block of the predictor space.

The CART idea

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

A tree creates terminal regions R1,…,RMR_1,\ldots,R_M and predicts a constant within each region:

f̂(x)=∑m=1Mcm𝟙(x∈Rm). \hat f(x)=\sum_{m=1}^{M}c_m\,\mathbb 1(x\in R_m).

Example rule path:

time<5 min→score diff>3→home possession→p̂=0.88. \text{time}<5\text{ min} \rightarrow \text{score diff}>3 \rightarrow \text{home possession} \rightarrow \hat p=0.88.

For classification, a leaf predicts class probabilities. For regression, a leaf predicts the mean response. The tree is interpretable because every prediction follows a sequence of if/then rules.

Impurity for classification trees

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

How do classification trees split a node?

For node RR with class (kk) proportions pkRp_{kR}, Gini impurity is

G(R)=1−∑k=1KpkR2. G(R)=1-\sum_{k=1}^{K}p_{kR}^{2}.

For binary outcomes, G(R)=2pR(1−pR)G(R)=2p_R(1-p_R).

Entropy is

H(R)=−∑k=1KpkRlog⁡2(pkR). H(R)=-\sum_{k=1}^{K}p_{kR}\log_2(p_{kR}).

Both equal zero in a pure node and are largest at a 50/50 split.

Impurity for classification trees

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

A candidate split ss divides a parent node RR into children RleftR_{\mathrm{left}} and RrightR_{\mathrm{right}}. Its improvement is

ΔI(s,R)=I(R)−nleftnI(Rleft)−nrightnI(Rright), \Delta I(s,R) =I(R)-\frac{n_{\mathrm{left}}}{n}I(R_{\mathrm{left}}) -\frac{n_{\mathrm{right}}}{n}I(R_{\mathrm{right}}),

where nn is the number of observations in the parent node, and nleftn_{\mathrm{left}} and nrightn_{\mathrm{right}} are the numbers in the left and right children.

At a node, CART evaluates the allowable variable-threshold pairs and chooses

s*=arg⁡maxsΔI(s,R). s^*=\arg\max_s \Delta I(s,R).

Numerical classification example: parent node

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

Suppose a node contains 6 home wins and 4 losses:

p=610=0.6,G(P)=1−(0.62+0.42)=0.48. p=\frac{6}{10}=0.6, \qquad G(P)=1-(0.6^2+0.4^2)=0.48.

A candidate split gives:

  • left: 5 wins, 1 loss;
  • right: 1 win, 3 losses.

Numerical classification example: child nodes

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

G(L)=1−[(56)2+(16)2]=0.278, G(L)=1-\left[\left(\frac56\right)^2+\left(\frac16\right)^2\right]=0.278,

G(R)=1−[(14)2+(34)2]=0.375. G(R)=1-\left[\left(\frac14\right)^2+\left(\frac34\right)^2\right]=0.375.

Weight by child sizes:

Gchildren=610(0.278)+410(0.375)=0.317. G_{\text{children}}=\frac6{10}(0.278)+\frac4{10}(0.375)=0.317.

The impurity decrease is 0.480−0.317=0.1630.480-0.317=0.163.

How recursive partitioning builds a tree

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

Starting with all training observations in the root node, CART repeats the following operations:

  1. Generate candidate splits for every eligible predictor.
  2. Calculate ΔI(s,R)\Delta I(s,R) for every candidate.
  3. Select the candidate with the largest reduction in impurity.
  4. Send observations to the two child nodes.
  5. Repeat within each child until a stopping rule is reached.

Regression trees

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

The prediction in region RmR_m is the regional mean:

ŷR=1nR∑i:xi∈Ryi. \hat y_R=\frac{1}{n_R}\sum_{i:x_i\in R}y_i.

The split minimizes

SSE⁡split=∑i:xi∈RL(yi−y‾RL)2+∑i:xi∈RR(yi−y‾RR)2. \operatorname{SSE}_{\text{split}} =\sum_{i:x_i\in R_L}(y_i-\bar y_{R_L})^2 +\sum_{i:x_i\in R_R}(y_i-\bar y_{R_R})^2.

For NFL data, yy could be final home margin rather than a win indicator.

Cost-complexity pruning

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

Cost-complexity pruning chooses a subtree TT by minimizing

Rα(T)=R(T)+α|T|, R_\alpha(T)=R(T)+\alpha|T|,

where R(T)R(T) is training error and |T||T| is the number of terminal nodes.

  • small α\alpha: larger tree;
  • large α\alpha: smaller tree;
  • select α\alpha using validation or cross-validation performance.

One tree is interpretable but unstable

SGMT 431 · Lecture 2.2 · Classification and Regression Trees (CART)

Small changes in the sample can change early splits and therefore the entire downstream tree.

2.3 Bagging and Random Forests

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

Reduce tree variance by averaging diverse bootstrap models.

Why average trees?

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

A single deep tree has low bias but high variance. Bagging reduces variance by fitting trees to different bootstrap samples and averaging their predictions.

For classification probability with BB bootstrap samples:

p̂bag(x)=1B∑b=1Bp̂*(b)(x). \hat p_{\text{bag}}(x)=\frac1B\sum_{b=1}^{B}\hat p^{*(b)}(x).

Each deep tree is noisy; averaging cancels part of that noise.

Averaging works best when trees are less correlated

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

If each tree prediction has variance σ2\sigma^2 and pairwise correlation ρ\rho, then

Var⁡{p̂bag(x)}=ρσ2+1−ρBσ2. \operatorname{Var}\{\hat p_{bag}(x)\} =\rho\sigma^2+\frac{1-\rho}{B}\sigma^2.

As B→∞B\rightarrow\infty,

Var⁡{p̂bag(x)}→ρσ2. \operatorname{Var}\{\hat p_{bag}(x)\}\rightarrow\rho\sigma^2.

More trees reduce the independent component of variance, but correlated trees leave a variance floor.

Bootstrap samples

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

A bootstrap sample contains n observations drawn with replacement from n training observations. Some observations appear multiple times and approximately 36.8% are omitted from a particular sample.

For a training set of size nn, the chance a row is absent from one bootstrap sample is

(1−1n)n→e−1≈0.368. \left(1-\frac1n\right)^n\longrightarrow e^{-1}\approx0.368.

Those out-of-bag rows can evaluate the corresponding tree without a separate resample.

For sports data, bootstrap games or use grouped resampling when rows within a game are dependent.

Fit bagged trees

Vote share is not a probability

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

predict() on a bagged classifier can return two very different quantities.

  • aggregation = "majority", the ipred default, returns the fraction of trees that voted for each class. When every tree agrees, the reported value is exactly 0 or 1. For example, for a game state x, 10 trees predicts 6 wins and 4 losses, the majority probability is then 6/10=0.66/10=0.6.
  • aggregation = "average" averages the trees’ leaf probabilities. This is the ensemble probability defined above. For example, for a game state x, 10 trees predicts 10 probabilities of home-team winning. Then the average of these 10 probabilities is the average probability.
bagged_votes <- predict(
  bagged_fit,
  newdata = validation_data,
  type = "prob",
  aggregation = "majority"
)[, "win"]

bagged_probability <- predict(
  bagged_fit,
  newdata = validation_data,
  type = "prob",
  aggregation = "average"
)[, "win"]

From bagging to random forests

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

At every split, a random forest considers only a random subset of mtrym_{\text{try}} predictors.

bootstrap rows+random feature candidates⇒less correlated trees. \text{bootstrap rows} +\text{random feature candidates} \Rightarrow \text{less correlated trees}.

The random-forest algorithm:

For b=1,…,Bb=1,\ldots,B tree:

  1. Draw a bootstrap sample of the training games or observations nn.
  2. Grow an unpruned tree on that sample.
  3. At each node, draw mm of the pp predictors.
  4. Search for the best split using only those mm candidates.
  5. Continue until a node-size or depth rule stops growth.

Fit a random forest in R

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

ranger is preferred over randomForest: far faster, and probability = TRUE averages leaf probabilities instead of counting votes.

forest_fit <- ranger(
  home_win_factor ~ game_seconds_remaining + home_score_diff +
    home_possession + down + ydstogo + yardline_100 +
    home_timeouts + away_timeouts,
  data = analysis_data,
  probability = TRUE,      # probability forest, not a vote count
  num.trees = 400,
  mtry = 3,
  min.node.size = 50,
  importance = "permutation",
  seed = 431               # ranger has its own RNG stream
)
  • smaller mtry: more diversity, potentially more bias;
  • larger mtry: stronger individual trees, more correlation;
  • min.node.size: terminal node size, the main control on tree depth.

The printed summary reports OOB error as a Brier score, not a misclassification rate — a proper scoring rule, straight out of the box. That is the substantive reason to prefer ranger here, not just the speed.

Random-forest feature importance: impurity

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

For mean decrease impurity (MDI), every split using feature jj contributes its weighted reduction in impurity.

For a forest with BB trees,

IMDI(j)=1B∑b=1B∑s∈Tb:v(s)=jnsnΔIs. I_{\text{MDI}}(j) = \frac{1}{B}\sum_{b=1}^{B} \sum_{s\in T_b:\,v(s)=j} \frac{n_s}{n}\Delta I_s.

  • v(s)=jv(s)=j: split ss uses feature jj
  • ns/nn_s/n: fraction of training observations reaching the split
  • ΔIs\Delta I_s: reduction in Gini impurity from that split
  • Add contributions across splits, then average across trees

A variable receives high MDI when it is used frequently and produces large impurity reductions, especially near the top of trees.

Random-forest feature importance: impurity

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

For example, suppose a tree uses score difference twice. At the root:

10001000(0.50−0.30)=0.20 \frac{1000}{1000}(0.50-0.30)=0.20

Later in the tree:

3001000(0.30−0.20)=0.03 \frac{300}{1000}(0.30-0.20)=0.03

So the impurity importance from this tree is 0.20+0.03=0.23. 0.20+0.03=0.23.

A random forest adds these contributions across all trees and averages them.

Built-in importance answers “how did this model split?”—not “what causes wins?”

Random-forest feature importance: permutation

SGMT 431 · Lecture 2.3 · Bagging and Random Forests

Permutation importance asks a different question: How much worse does the fitted model predict when feature jj is made uninformative?

Iperm(j)=L(y,p̂(Xjperm))−L(y,p̂(X)). I_{\text{perm}}(j) = L\!\left(y,\hat p(X_j^{\text{perm}})\right) - L\!\left(y,\hat p(X)\right).

  1. Calculate the baseline prediction loss.
  2. Randomly shuffle feature jj.
  3. Predict again without refitting the forest.
  4. Measure how much the loss increases

For example, if validation log loss changes from

0.52→0.60, 0.52 \longrightarrow 0.60,

then

Iperm(j)=0.60−0.52=0.08. I_{\text{perm}}(j)=0.60-0.52=0.08.

A larger increase means predictions depend more strongly on that feature.

2.4 Gradient Boosting and XGBoost

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

Fit small trees sequentially to reduce the current model’s loss.

Boosting versus bagging

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

An additive boosted model is

FM(x)=F0(x)+ν∑m=1Mfm(x), F_M(x)=F_0(x)+\nu\sum_{m=1}^{M}f_m(x),

where fmf_m is a small tree and 0<ν≤10<\nu\le1 is the learning rate.

  • bagging: independently fit strong trees, then average;
  • boosting: sequentially fit weak trees to improve the current model.

Gradient boosting as stagewise optimization

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

At round mm, calculate pseudo-residuals

rim=−∂L(yi,F(xi))∂F(xi)|F=Fm−1. r_{im}=-\left. \frac{\partial L(y_i,F(x_i))}{\partial F(x_i)} \right|_{F=F_{m-1}}.

Fit a regression tree fm(x)f_m(x) to rimr_{im}, then update

Fm(x)=Fm−1(x)+νfm(x). F_m(x)=F_{m-1}(x)+\nu f_m(x).

The tree approximates the direction that most rapidly reduces loss.

Logistic-loss gradients have a simple meaning

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

For a logit FiF_i, pi=σ(Fi)p_i=\sigma(F_i) and

Li=−yilog⁡pi−(1−yi)log⁡(1−pi). L_i=-y_i\log p_i-(1-y_i)\log(1-p_i).

Then

gi=∂Li∂Fi=pi−yi,hi=∂2Li∂Fi2=pi(1−pi). g_i=\frac{\partial L_i}{\partial F_i}=p_i-y_i, \qquad h_i=\frac{\partial^2L_i}{\partial F_i^2}=p_i(1-p_i).

The negative gradient is yi−piy_i-p_i: observed outcome minus current probability.

A one-step numerical example

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

Suppose p=(.50,.50,.50)p=(.50,.50,.50) and y=(1,0,1)y=(1,0,1).

−g=y−p=(.50,−.50,.50). -g=y-p=(.50,-.50,.50).

If a new tree predicts f1=(.40,−.20,.40)f_1=(.40,-.20,.40) and ν=.10\nu=.10:

F1=0+.10f1=(.04,−.02,.04), F_1=0+.10f_1=(.04,-.02,.04),

p1=σ(F1)=(.510,.495,.510). p_1=\sigma(F_1)=(.510,.495,.510).

The update is intentionally small.

XGBoost adds a regularized second-order objective

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

At boosting round tt, approximate the objective:

ℒ(t)≈∑i[gift(xi)+12hift(xi)2]+Ω(ft), \mathcal L^{(t)} \approx\sum_i\left[g_i f_t(x_i)+\frac12h_i f_t(x_i)^2\right] +\Omega(f_t),

with tree penalty

Ω(f)=γT+12λ∑j=1Twj2. \Omega(f)=\gamma T+\frac12\lambda\sum_{j=1}^{T}w_j^2.

TT is the number of leaves and wjw_j is leaf jj’s score.

Deep dive: derive the optimal leaf weight

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

For one leaf with gradient and Hessian sums

G=∑i∈Rgi,H=∑i∈Rhi, G=\sum_{i\in R}g_i, \qquad H=\sum_{i\in R}h_i,

its approximate objective is

Gw+12(H+λ)w2. Gw+\frac12(H+\lambda)w^2.

Setting the derivative to zero gives

w*=−GH+λ. w^*=-\frac{G}{H+\lambda}.

Regularization shrinks unstable leaf updates.

Deep dive: accept a split only when gain is positive

SGMT 431 · Lecture 2.4 · Gradient Boosting and XGBoost

Gain⁡=12[GL2HL+λ+GR2HR+λ−(GL+GR)2HL+HR+λ]−γ. \operatorname{Gain} =\frac12\left[ \frac{G_L^2}{H_L+\lambda} +\frac{G_R^2}{H_R+\lambda} -\frac{(G_L+G_R)^2}{H_L+H_R+\lambda} \right]-\gamma.

For (GL,HL)=(−3,2)(G_L,H_L)=(-3,2), (GR,HR)=(2,3)(G_R,H_R)=(2,3), and λ=1\lambda=1:

Gain⁡=12(93+44−16)−γ=1.917−γ. \operatorname{Gain} =\frac12\left(\frac9{3}+\frac4{4}-\frac1{6}\right)-\gamma =1.917-\gamma.

If γ=2\gamma=2, the split is rejected.

Gain importance normalizes retained split gains

Raw gain for feature jj is

Gj=∑s:v(s)=jGain⁡(s). G_j=\sum_{s:\,v(s)=j}\operatorname{Gain}(s).

Reported gain importance is

Ijgain=Gj∑kGk. I_j^{\text{gain}}=\frac{G_j}{\sum_kG_k}.

An importance of .40 means splits using that feature produced 40% of summed retained training-objective improvement.

It gives no effect direction and may divide importance unpredictably among correlated predictors.

2.5 LightGBM and CatBoost

SGMT 431 · Lecture 2.5 · LightGBM and CatBoost

Compare two boosting systems designed for speed and categorical predictors.

LightGBM searches efficiently with histograms

SGMT 431 · Lecture 2.5 · LightGBM and CatBoost

LightGBM typically:

  • bins continuous features into histograms;
  • grows the leaf with the largest estimated loss reduction;
  • can sample observations with large gradients more heavily;
  • handles missing values within split search.

Leaf-wise growth can improve loss quickly, but num_leaves, min_data_in_leaf, and depth constraints are essential on small data.

[Sources] - https://lightgbm.readthedocs.io/ [/Sources]

CatBoost controls categorical-target leakage

SGMT 431 · Lecture 2.5 · LightGBM and CatBoost

A naive target mean for category cc is

y‾c=∑i𝟙(xi=c)yi∑i𝟙(xi=c), \bar y_c=\frac{\sum_i\mathbb 1(x_i=c)y_i} {\sum_i\mathbb 1(x_i=c)},

but it uses each observation’s own target.

CatBoost uses ordered statistics from observations earlier in a random permutation:

TS⁡i(c)=∑j<i𝟙(xj=c)yj+aP∑j<i𝟙(xj=c)+a. \operatorname{TS}_i(c)= \frac{\sum_{j<i}\mathbb 1(x_j=c)y_j+aP} {\sum_{j<i}\mathbb 1(x_j=c)+a}.

This regularizes rare categories and reduces target leakage.

[Sources] - https://catboost.ai/docs/ [/Sources]

2.6 Model Evaluation and Calibration

SGMT 431 · Lecture 2.6 · Model Evaluation and Calibration

Judge the complete probability, not only the predicted class or ranking.

Model evaluation

SGMT 431 · Lecture 2.6 · Model Evaluation and Calibration

What metrics should be used to evaluate win probability models?

Previously, performance has been measured using Brier score and log loss.

But what about accuracy? Is prediction accuracy a reliable metric for evaluating probability models?

A scoring rule is proper when honesty wins

SGMT 431 · Lecture 2.6 · Model Evaluation and Calibration

A scoring rule in probability measures the accuracy of a probabilistic forecast by assigning a numerical penalty or reward based on a prediction and the actual outcome that occurs.

The forecaster knows the true probability qq and reports pp. Its expected penalty is

S‾(p,q)=qS(p,1)+(1−q)S(p,0). \bar S(p,q)=q\,S(p,1)+(1-q)\,S(p,0). A scoring rule is - proper: p=qp=q is a minimizer of S‾(p,q)\bar S(p,q) for every qq - strictly proper: p=qp=q is the only minimizer

Strict propriety is what forces a model to say what it actually believes. Without it, a metric can be improved by lying.

Ask the class what a forecaster would report if it were paid on accuracy alone. Someone will say “always 0 or 1” — that is exactly the answer, and it is the whole argument in one line.

Brier and log loss are both strictly proper

SGMT 431 · Lecture 2.6 · Model Evaluation and Calibration

Brier, with S(p,y)=(y−p)2S(p,y)=(y-p)^2:

S‾(p,q)=q(1−p)2+(1−q)p2=q(1−q)⏟irreducible+(p−q)2⏟cost of lying \bar S(p,q)=q(1-p)^2+(1-q)p^2 =\underbrace{q(1-q)}_{\text{irreducible}}+\underbrace{(p-q)^2}_{\text{cost of lying}}

Log loss, with S(p,y)=−[ylog⁡p+(1−y)log⁡(1−p)]S(p,y)=-[y\log p+(1-y)\log(1-p)]:

S‾(p,q)−S‾(q,q)=DKL(q∥p)≥0 \bar S(p,q)-\bar S(q,q)=D_{\mathrm{KL}}(q\,\|\,p)\ge 0

Both have the same shape — an irreducible term the forecaster cannot touch, plus a penalty that is zero only at p=qp=q.

Accuracy is not a proper scoring rule

SGMT 431 · Lecture 2.6 · Model Evaluation and Calibration

Threshold tt; predict 1 when p≥tp\ge t. Then

S‾acc(p,q)={1−q,p≥t,q,p<t. \bar S_{\mathrm{acc}}(p,q)= \begin{cases} 1-q, & p\ge t,\\[2pt] q, & p<t. \end{cases}

The report enters only through which side of tt it lands on.

  • Not strictly proper. t=.5t=.5, q=.70q=.70: reporting .70.70, .51.51, or 1.001.00 all score .30.30. An infinite set of reports ties with the truth.
  • Not even proper for t≠.5t\neq.5. t=.30t=.30, q=.40q=.40: honesty predicts 1 and is wrong 60% of the time; reporting .20.20 predicts 0 and is wrong 40%. Lying strictly wins.

Never select, tune, or rank a probability model on accuracy.

2.7 Tuning and Feature Importance

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance

Choose complexity on validation games, then explain the fitted model with a clearly defined importance measure.

Tune in an order that controls the largest risks

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance
  1. fix grouped, chronological resampling;
  2. choose a proper scoring rule;
  3. constrain tree size or leaf size;
  4. tune feature and row subsampling;
  5. tune learning rate and number of rounds together;
  6. inspect calibration and stability;
  7. evaluate once on the untouched test season.

Focus on the high-impact parameters

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance
Family High-impact parameters
CART depth, minimum leaf size, complexity penalty
random forest mtry, minimum node size, number of trees
boosting learning rate, rounds, leaves/depth, minimum child weight
all ensembles row subsampling, feature subsampling, class weights

Start with controls that directly affect variance, smoothness, and optimization length.

Tune learning rate and tree count together

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance

For boosted models,

FM(x)=F0(x)+ν∑m=1Mfm(x). F_M(x)=F_0(x)+\nu\sum_{m=1}^{M}f_m(x).

A smaller ν\nu usually requires a larger MM.

  • high ν\nu, few trees: fast, potentially unstable;
  • low ν\nu, many trees: smoother, more computation;
  • early stopping estimates a useful MM for each ν\nu.

Never let the test set choose parameters

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance

training games⏟fit parametersvalidation games⏟choose hyperparameterstest games⏟final estimate only \underbrace{\text{training games}}_{\text{fit parameters}} \quad \underbrace{\text{validation games}}_{\text{choose hyperparameters}} \quad \underbrace{\text{test games}}_{\text{final estimate only}}

Repeatedly checking the test set turns it into another validation set and destroys the final performance estimate.

Permutation importance uses held-out loss

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance

Let L0L_0 be baseline validation loss. After permuting feature jj in repeat bb, recalculate Lj(b)L_j^{(b)}:

Ijperm=1B∑b=1B(Lj(b)−L0). I_j^{\text{perm}} =\frac1B\sum_{b=1}^{B}\left(L_j^{(b)}-L_0\right).

Large positive importance means the fitted model relied on that feature for held-out predictions.

Correlated predictors may mask one another; permutation can also create unrealistic combinations.

Calculate permutation importance in R

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance
baseline <- log_loss(validation$home_win, p_hat)

importance_j <- replicate(20, {
  shuffled <- validation
  shuffled[[feature_j]] <- sample(shuffled[[feature_j]])
  p_shuffled <- predict_probability(fit, shuffled)
  log_loss(shuffled$home_win, p_shuffled) - baseline
}) %>%
  mean()

Use game-level or conditional permutation if row shuffling violates the data structure.

PDP and SHAP describe effects—not causal effects

SGMT 431 · Lecture 2.7 · Tuning and Feature Importance

PD̂j(z)=1n∑i=1nf̂(z,xi,−j),f̂(x)=ϕ0+∑j=1pϕj. \widehat{PD}_j(z)=\frac1n\sum_{i=1}^{n}\hat f(z,x_{i,-j}), \qquad \hat f(x)=\phi_0+\sum_{j=1}^{p}\phi_j.

  • PDP: average modeled relationship;
  • SHAP: local additive attribution;
  • neither proves that changing a feature causes win probability to change.

Six decisions organize the complete workflow

SGMT 431 · Lecture 2 · Synthesis
  1. Start with a transparent probability benchmark.
  2. Keep games together and future information out.
  3. Know the objective each algorithm optimizes.
  4. Tune complexity on validation games.
  5. Evaluate probability accuracy and calibration.
  6. Define feature importance before interpreting it.

Prefer the simplest model that delivers stable, calibrated performance for the intended use.
